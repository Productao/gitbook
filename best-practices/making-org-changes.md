# Making Org Changes

Organizational changes—reorgs, restructuring, role changes—are some of the most impactful decisions leadership makes. This guide covers best practices for planning, testing, communicating, and implementing org changes using Agentnoon.

## Types of Organizational Changes

### **1. Structural Changes**
- Merging or splitting departments
- Creating new teams or business units
- Changing reporting relationships
- Adding or removing management layers
- Centralizing or decentralizing functions

### **2. Position Changes**
- Adding new positions (hiring, backfills, new roles)
- Closing positions (RIFs, budget cuts, role elimination)
- Moving positions between departments
- Changing position attributes (title, salary, level)

### **3. Employee Changes**
- Promotions and title changes
- Transfers between teams
- Salary adjustments
- Role reassignments

### **4. Strategic Workforce Changes**
- Geographic expansion (new offices, remote workforce)
- Scaling teams for growth
- Cost reduction initiatives
- Post-acquisition integration

---

## Core Principle: Always Use Scenarios

**Never make organizational changes directly in Main Org.**

### Why Scenarios Are Essential

**1. Test Before You Implement**
- See the full impact before committing
- Identify unintended consequences (broken hierarchies, SOC issues, budget overruns)
- Compare multiple approaches side-by-side

**2. Get Stakeholder Buy-In**
- Show leadership the plan before executing
- Incorporate feedback without undoing work
- Build consensus around the change

**3. Approval Workflows**
- Submit scenarios for formal approval
- Track who approved what and when
- Maintain audit trail for governance

**4. Preserve Optionality**
- Create multiple scenario versions (Plan A, Plan B, Plan C)
- Compare trade-offs before deciding
- Delete scenarios that don't work—no harm done

**5. Communicate Clearly**
- Show before/after comparisons
- Visualize the new org structure
- Export scenario data for presentations

## Planning Organizational Changes

### Step 1: Define the Problem or Goal

**Before making changes, clarify:**
- **What problem are we solving?** (e.g., Sales team lacks capacity, Engineering managers are overloaded)
- **What's the goal?** (e.g., Reduce average SOC to 7, cut workforce cost by $2M)
- **What's the timeline?** (e.g., Implement by Q3, phase over 6 months)
- **What are the constraints?** (e.g., $500K budget, can't exceed 20 headcount, must preserve key talent)

**Example goals:**
- "Restructure Engineering into 3 product-focused teams to improve accountability"
- "Reduce Operations headcount by 15% while maintaining service levels"
- "Add 50 sales roles by year-end to support aggressive growth targets"

### Step 2: Research and Gather Data

**Understand the current state:**
- What's the current org structure?
- What are the key metrics? (SOC, cost, headcount, layers)
- Where are the pain points? (overloaded managers, redundant roles, high-cost departments)
- What's worked well? (successful teams, efficient structures)

**In Agentnoon:**
- View Main Org org chart to understand current structure
- Use Workforce Hub to identify SOC issues, cost distribution, headcount by department
- Apply filters to drill into specific areas (e.g., Engineering only)
- Export directory view to analyze data in Excel

### Step 3: Design the Future State

**Define the target org structure:**
- What departments/teams will exist?
- Who reports to whom?
- What positions are added, closed, or moved?
- What's the expected cost and headcount?

**Considerations:**
- **Span of Control:** Aim for 5-10 direct reports per manager (depends on context)
- **Layers:** Minimize unnecessary management layers (flatten where possible)
- **Specialization vs. Generalization:** Group by function (Engineering, Sales) or by product (Product A Team, Product B Team)?
- **Geographic distribution:** Centralized teams or distributed by location?
- **Cost efficiency:** Higher-cost structure with better outcomes, or leaner structure with trade-offs?

### Step 4: Create a Scenario

**In Agentnoon:**
1. Create a new scenario (name it descriptively: "Q3 2026 Engineering Reorg")
2. Use a meaningful description ("Restructure Engineering into 3 product-focused teams with dedicated managers")
3. Set a budget if applicable (e.g., neutral budget for reorg, -$2M budget for RIF)

## Testing Changes Before Implementation

### Model the Change in Your Scenario

**Add positions:**
- New roles required (e.g., 3 new Engineering Managers)
- Set hire dates for phased implementation
- Use rate cards to auto-populate salaries

**Close positions:**
- Positions to eliminate (redundant roles, budget cuts)
- Set effective dates when closures take effect
- Track cost savings in Change Tracker

**Move positions:**
- Reassign positions to new managers or departments
- Change reporting relationships
- Use effective dates to phase moves over time

**Modify positions:**
- Change titles, salaries, levels
- Update department assignments
- Adjust FTE or location

### Analyze the Impact

**Use Agentnoon's built-in tools:**

**1. Change Tracker (OpEx Panel)**
- View net headcount change (+10, -5, net +5)
- View net cost change (+$500K, -$200K, net +$300K)
- See additions (green), reductions (red), modifications (blue)

**2. Org Chart View**
- Visualize the new structure
- Check reporting relationships
- Verify no broken hierarchies (orange link icon)

**3. Span of Control Metrics**
- Identify managers with high SOC (>10 direct reports)
- Identify managers with low SOC (<3 direct reports)
- Aim for balanced SOC across the organization

**4. Forecast View**
- See how changes impact cost and headcount over time
- Toggle to monthly/quarterly view to see phased changes
- Use Show Changes to see before/after delta

**5. Directory View**
- Review all changes in table format
- Sort and filter to find specific modifications
- Export to CSV for detailed analysis

### Iterate and Refine

**After analyzing impact:**
- Adjust the plan to address issues (SOC problems, cost overruns, timing concerns)
- Test alternative approaches (create Scenario B, Scenario C)
- Compare scenarios using Forecast exports
- Refine until you have a plan that meets goals within constraints

## Communicating Org Changes

### Internal Communication Strategy

**Who needs to know:**
- Affected employees (people whose roles change)
- Department leaders (whose teams are impacted)
- Finance (budget and cost implications)
- HR (recruiting, onboarding, offboarding)
- Executive leadership (approval and strategic alignment)
- All employees (if org-wide change)

**What to communicate:**
- **Rationale:** Why is this change happening?
- **Impact:** Who's affected, what's changing, when it happens
- **Benefits:** What we gain from this change (efficiency, growth, clarity)
- **Next steps:** What happens next, timeline, how to ask questions

### Using Agentnoon to Support Communication

**1. Before/After Org Charts**
- Export current org chart (Main Org)
- Export future org chart (Scenario)
- Use PowerPoint export to create visual slides
- Show side-by-side comparison

**2. Change Summary Reports**
- Export Change Tracker to CSV
- Summarize: +X positions added, -Y positions closed, Z positions moved
- Show net cost impact (+$500K) and net headcount impact (+10)

**3. Department-Specific Impacts**
- Filter scenario to specific department
- Export department's before/after data
- Share with department leader for review

**4. Timeline Visualization**
- Use Forecast (monthly or quarterly view) to show when changes happen
- Export to CSV, create Gantt chart or timeline in PowerPoint
- Show phased approach (Q1: add managers, Q2: move teams, Q3: finalize structure)

### Presentation Tips

**Executive presentations:**
- Lead with the "why" (problem statement and goal)
- Show high-level metrics (total cost, headcount, key changes)
- Highlight risks and mitigation strategies
- Request approval or feedback

**Department leader presentations:**
- Focus on their team specifically
- Show before/after org chart for their area
- Explain reporting relationship changes
- Answer questions and address concerns

**All-hands presentations:**
- Emphasize rationale and benefits
- Acknowledge that change is difficult
- Provide resources for employees to ask questions
- Set clear timeline and next steps

## Getting Approvals and Buy-In

### Formal Approval Workflow

**In Agentnoon:**
1. Finalize your scenario
2. Open the OpEx Panel (Scenario Impacts and Changes)
3. Click "Configure Submission"
4. Add justification explaining the change
5. Select scenario-specific approvers (Level 0, Level 3) if needed
6. Submit for approval

**Approval flow:**
- Level 0 (scenario-specific, optional) → Level 1 (global) → Level 2 (global) → Level 3 (scenario-specific, optional)
- Approvers review each change (additions, closures, moves)
- Approvers approve or reject with comments
- If rejected, scenario returns to you for revisions

**See:** [Configuring Approval Flows](../admin/configuring-approval-flows.md)

### Building Consensus Before Formal Approval

**Informal stakeholder alignment:**
- Share scenario with key stakeholders before submitting for approval
- Gather feedback in 1:1s or small group meetings
- Incorporate feedback into scenario
- Pre-socialize with approvers to increase likelihood of approval

**Addressing concerns:**
- **Cost concerns:** Show trade-offs (higher cost for better outcomes, or cost-neutral reorg)
- **Timing concerns:** Add effective dates to phase changes over time
- **Talent concerns:** Highlight which key employees are protected, which roles are at risk
- **Execution concerns:** Provide implementation plan and timeline

## Phasing Org Changes Over Time

### Why Phase Changes

**Benefits:**
- Reduce disruption (not all changes at once)
- Allow time to hire into new positions before closing old ones
- Test early phases before committing to later phases
- Adjust based on feedback from Phase 1

**Example:**
- **Phase 1 (Q1):** Add 3 Engineering Managers
- **Phase 2 (Q2):** Reassign engineers to new managers
- **Phase 3 (Q3):** Close 2 redundant manager positions

### Using Effective Dates in Agentnoon

**How to phase:**
1. Make all changes in your scenario (add, close, move positions)
2. Assign effective dates to each change
   - Additions with effective date = hire date
   - Closures with effective date = termination date
   - Moves/modifications with effective date = date change takes effect
3. View in Forecast (monthly or quarterly) to see timeline
4. Export to show stakeholders exactly when each change happens

**Example:**
- Add "Engineering Manager - Product A" with effective date January 1, 2026
- Move 8 engineers to report to new manager with effective date January 15, 2026
- Close "Engineering Manager - Infrastructure" with effective date February 1, 2026

**Result in Forecast:**
- January: +1 headcount (new manager added)
- February: -1 headcount (old manager closed)
- Net: Headcount neutral reorg

## Documenting Rationale for Changes

### Why Documentation Matters

- **Audit trail:** Understand why decisions were made months or years later
- **Organizational memory:** New leaders can understand past decisions
- **Governance:** Demonstrate thoughtful, deliberate planning process
- **Learning:** Document what worked and what didn't for future reorgs

### What to Document

**In Agentnoon:**
- **Scenario name:** Descriptive (e.g., "Q3 2026 Engineering Reorg - Product-Focused Teams")
- **Scenario description:** Brief summary of the change and goal
- **Justification (in approval submission):** Detailed rationale, expected outcomes, risks and mitigation
- **Comments:** Internal notes about decisions made, feedback received, trade-offs considered

**Outside Agentnoon:**
- **Planning documents:** Detailed memos, stakeholder feedback, decision frameworks
- **Meeting notes:** Discussions with leadership, department leaders, Finance, HR
- **Post-implementation review:** What went well, what didn't, lessons learned

## Implementing Approved Changes

### After Approval: Execution Plan

**Your scenario is approved. Now what?**

**Step 1: Communicate the Plan**
- Announce changes to affected employees
- Share timeline and next steps
- Provide resources for questions and support

**Step 2: Execute in Phases (if phased)**
- **Phase 1:** Add new positions first (if applicable)
  - Post job descriptions for new roles
  - Recruit and hire into new positions
  - Onboard new employees
- **Phase 2:** Move existing positions/employees
  - Update reporting relationships
  - Communicate changes to affected employees
  - Update systems (HRIS, email distribution lists, Slack channels)
- **Phase 3:** Close positions (if applicable)
  - Conduct layoffs or role eliminations
  - Provide severance and support
  - Update Main Org to reflect closures

**Step 3: Update Main Org**
- After implementing changes in the real world, update Main Org data
- Upload new CSV with current structure
- Or wait for next scheduled data sync (if using live integration)
- Verify Main Org reflects the new structure

**Step 4: Monitor and Adjust**
- Track key metrics (SOC, cost, headcount) post-implementation
- Gather feedback from employees and managers
- Identify issues early (overloaded managers, unclear roles, broken processes)
- Make minor adjustments as needed

## Tracking Post-Implementation Results

### Did the Change Achieve the Goal?

**Measure against original goals:**
- **Goal:** Reduce average SOC to 7 → **Result:** Average SOC now 6.5 ✅
- **Goal:** Cut workforce cost by $2M → **Result:** Saved $2.1M ✅
- **Goal:** Improve Engineering velocity → **Result:** Measure sprint velocity, feature delivery, eng satisfaction

**In Agentnoon:**
- View Main Org metrics after implementation
- Compare to pre-change metrics (export historical data for comparison)
- Use Workforce Hub to analyze outcomes (SOC distribution, cost by department, headcount trends)

**Qualitative feedback:**
- Employee surveys (do employees understand the new structure?)
- Manager feedback (are reporting relationships working?)
- Executive assessment (did we achieve strategic goals?)

### Course Correction

**If the change isn't working:**
1. Identify specific issues (too many layers, wrong reporting relationships, wrong roles)
2. Create a new scenario to adjust the structure
3. Model adjustments (add missing positions, move misplaced teams)
4. Submit for approval (if needed)
5. Implement adjustments

**It's okay to iterate.** Org changes are rarely perfect on the first try. Continuous improvement is expected.

## Common Pitfalls and How to Avoid Them

### Pitfall #1: Changing Too Much at Once
**Problem:** Massive reorg affecting 50% of the company all on the same day.

**Impact:** Confusion, low morale, execution breakdown, loss of productivity.

**Solution:** Phase changes over 3-6 months. Start with management structure, then move teams, then finalize.

### Pitfall #2: Not Getting Buy-In from Key Stakeholders
**Problem:** Announce reorg without socializing it with department leaders first.

**Impact:** Resistance, pushback, employees hear from managers who don't understand the change.

**Solution:** Pre-socialize with leaders before announcing. Incorporate their feedback into the plan.

### Pitfall #3: Ignoring Span of Control
**Problem:** Create a structure where one manager has 25 direct reports.

**Impact:** Overloaded manager, lack of attention for reports, poor performance.

**Solution:** Use Agentnoon's SOC metrics to identify issues. Aim for 5-10 direct reports per manager.

### Pitfall #4: Not Communicating the "Why"
**Problem:** Announce structural change without explaining the rationale.

**Impact:** Employees fill the void with speculation, assume the worst, morale suffers.

**Solution:** Lead with the why. Explain the problem, the goal, and how this change helps.

### Pitfall #5: Making Changes Directly in Main Org
**Problem:** Skip scenarios and make changes directly in the live org.

**Impact:** No testing, no approval, no way to revert, mistakes are permanent.

**Solution:** Always use scenarios. Test, get approval, then implement in the real world and update Main Org.

## Change Management Best Practices

### 1. Start with the End in Mind
- Define the target state clearly
- Ensure leadership alignment on the goal
- Communicate the vision to employees

### 2. Involve Stakeholders Early
- Get input from department leaders
- Incorporate feedback from affected employees (where appropriate)
- Align with Finance and HR on budget and talent implications

### 3. Test Before You Execute
- Model changes in scenarios
- Identify unintended consequences
- Compare multiple approaches

### 4. Communicate Clearly and Often
- Explain the why, the what, and the when
- Provide forums for questions
- Follow up after implementation

### 5. Phase Changes Thoughtfully
- Break large changes into manageable phases
- Give employees time to adapt
- Course-correct between phases

### 6. Monitor and Iterate
- Track metrics post-implementation
- Gather feedback continuously
- Be willing to adjust
