# Scenario Protips

Master these best practices to become more efficient at scenario planning and avoid common pitfalls. These tips come from experienced Agentnoon users and best practices we've observed.

---

## Backup and Duplication

### ✅ Duplicate Scenarios Frequently

**Best practice:** Before making significant changes or trying advanced operations, duplicate your scenario to create a backup.

**Why it matters:**
- Scenarios can't be "undone" once changes are saved
- Advanced operations like refresh or merge can have unexpected results
- Having a backup lets you experiment freely without risk

**How to duplicate:**
1. Open the scenario you want to backup
2. Click the scenario actions menu (three dots)
3. Select "Duplicate Scenario"
4. Rename the duplicate with a clear identifier (e.g., "Q1 Hiring Plan - BACKUP 2026-02-18")

**When to duplicate:**
- Before performing scenario refresh
- Before merging scenarios
- Before making major bulk changes
- Before sharing with many collaborators
- Weekly backups of critical scenarios

## Organization and Naming

### ✅ Use Descriptive Scenario Names

**Good names:**
- "2026 Q1 Sales Reorg - West Coast"
- "Annual Hiring Plan - Engineering (v3)"
- "Budget Cut Scenario - 10% Reduction"

**Bad names:**
- "New Scenario"
- "Test"
- "Scenario 1"
- "Steve's Plan"

**Naming conventions to consider:**
- Include time period (Q1 2026, FY2027)
- Include purpose or action (Reorg, Hiring Plan, Budget Cut)
- Include scope (Engineering, Sales, Company-Wide)
- Include version if iterating (v1, v2, v3)

### ✅ Use Tags and Symbols Consistently

**Create a tagging system:**
- **Time-based tags:** "Q1 2026", "Q2 2026", "FY2027"
- **Status tags:** "Draft", "In Review", "Approved", "Implemented"
- **Type tags:** "Hiring Plan", "Reorg", "Budget Cut", "RIF"
- **Department tags:** "Engineering", "Sales", "G&A"

**Use symbols to communicate priority:**
- ⚡ High Priority / Urgent
- 🎯 Annual Plan / Strategic
- 💰 Budget-Related
- 👥 Hiring Plan
- 🔄 Reorganization
- ❌ RIF/Layoff
- ✅ Approved
- 🚧 Work in Progress

## Efficiency Tips

### ✅ Master Keyboard Shortcuts

**Essential shortcuts:**
- `3`: Switch to Org Chart view
- `5`: Switch to Directory view
- `CMD/CTRL + K`: Quick search
- `CMD/CTRL + S`: Save changes
- `CMD/CTRL + Z`: Undo last action

**Use shortcuts to:**
- Switch between views quickly
- Navigate without using mouse
- Speed up common operations

### ✅ Use Bulk Operations for Efficiency

**When to use bulk operations:**
- Moving entire teams between departments
- Adjusting salaries across a pay grade
- Closing multiple positions in a RIF
- Changing attributes for many positions

**How to bulk select:**
- Click "Select Team" to select a manager and all direct reports
- Hold SHIFT and click to select ranges in Directory view
- Use filters + "Select All" to select filtered subset

> **[Screenshot placeholder: Directory view with multiple positions selected and bulk edit panel open]**

### ✅ Use Filters to Focus Your Work

**Create saved filter views:**
- "Open Positions Only"
- "Engineering Department"
- "Positions Changed in This Scenario"
- "High Salary Positions (>$150K)"

**Benefits:**
- Reduce cognitive load by hiding irrelevant data
- Focus on specific segments you're planning
- Quickly find positions you need to modify

## Collaboration Best Practices

### ✅ Use Comments, Don't Just Make Changes

**Add context with comments:**
- Explain why you're making a change
- Tag stakeholders for input (@mention)
- Document assumptions or dependencies
- Note what still needs review

**Example comments:**
- "Moving this role to Sales based on discussion with @Jane from 2/15 planning meeting"
- "@Mike can you review this salary adjustment for market competitiveness?"
- "Placeholder hire date - waiting for headcount approval from Finance"

> **[Screenshot placeholder: Position card with comments panel showing conversation with @mentions]**

### ✅ Set Clear Ownership and Permissions

**Best practices:**
- Assign one primary owner per scenario
- Give edit access only to active collaborators
- Use view-only sharing for stakeholders who just need visibility
- Remove access when collaboration is complete

**Document ownership:**
- Add owner name to scenario description
- Use tags to indicate responsible team
- Set clear expectations for who makes final decisions

## Planning and Forecasting

### ✅ Use Effective Dates for Phased Planning

**Best practice:** Always set effective dates when changes happen at specific future times.

**Use effective dates for:**
- Staggered hiring across quarters
- Multi-phase reorganizations
- Budget cuts that happen mid-year
- Promotions with known start dates

**Why it matters:**
- Forecast view shows accurate timing
- Cost impact is properly phased
- Stakeholders see when changes take effect

**Example:**
- Q1 hires: Set hire dates in January-March
- Q2 reorg: Set effective date April 1
- Q3 promotions: Set effective date July 1

### ✅ Review Change Tracker Regularly

**Make it a habit:**
- Check Change Tracker after every major edit
- Validate headcount and cost impact matches your target
- Review department-by-department breakdown
- Use it to communicate with stakeholders

**What to look for:**
- Are you hitting your headcount target?
- Is the cost impact within budget?
- Are changes balanced across departments?
- Any unexpected impacts?

## Quality Control

### ✅ Use Show Before/After/Changes Views

**Best practice:** Don't just work in "Show After" mode. Toggle between views to understand impact.

**Workflow:**
1. **Show Before:** Understand your baseline
2. **Show After:** Make your changes
3. **Show Changes:** Validate what actually changed
4. Toggle back and forth to verify

**Why it matters:**
- Catch unintended changes
- Understand true impact
- Communicate more effectively
- Validate your work

### ✅ Validate in Multiple Views

**Check your scenario in:**
- **Org Chart:** Does the structure make sense visually?
- **Directory:** Are all attributes correct when reviewed in bulk?
- **Forecast:** Does the timing of changes look right?
- **Workforce Hub:** Are span of control and layers healthy?

**Different views reveal different issues:**
- Org Chart shows reporting structure problems
- Directory shows data consistency issues
- Forecast shows timing problems
- Hub shows organizational health issues

## Approval and Implementation

### ✅ Prepare Before Submitting for Approval

**Checklist before submission:**
- [ ] Scenario name is clear and descriptive
- [ ] Justification is thorough and specific
- [ ] All changes have been reviewed
- [ ] Cost impact is within expected range
- [ ] Headcount changes align with targets
- [ ] Effective dates are set correctly
- [ ] Stakeholders have been consulted
- [ ] Scenario has been validated in multiple views

### ✅ Export and Document Your Work

**Best practice:** Export key views before and after approval.

**What to export:**
- Org chart views for presentations
- Directory data for detailed analysis
- Forecast projections for budget planning
- Change summary from Change Tracker

**Why export:**
- Create audit trail
- Share with stakeholders who don't have Agentnoon access
- Include in business cases and planning documents
- Archive scenario state at key milestones

## Common Mistakes to Avoid

### ❌ Don't Make Changes Without Effective Dates

**Mistake:** Making changes to positions without setting effective dates when they happen in the future.

**Result:** Forecast shows changes as immediate, budget impact is misaligned with timing.

**Fix:** Always set hire dates, effective dates, or termination dates for time-specific changes.

### ❌ Don't Work on Very Old Scenarios

**Mistake:** Continuing to work on a scenario created months ago when Main Org has changed significantly.

**Result:** Your baseline is outdated, scenario may have positions that no longer exist.

**Fix:** Either create a new scenario from current Main Org, or use Scenario Refresh to update the baseline.

### ❌ Don't Forget to Save Regularly

**Mistake:** Making many changes without saving, then losing work if browser crashes.

**Result:** Lost work, frustration, need to redo changes.

**Fix:** Use `CMD/CTRL + S` frequently, or enable auto-save if available.

### ❌ Don't Share Edit Access Too Broadly

**Mistake:** Giving edit access to everyone who needs visibility.

**Result:** Unintended changes, conflicting edits, confusion about who made what change.

**Fix:** Use view-only sharing for stakeholders, limit edit access to active collaborators.

### ❌ Don't Skip the "Show Changes" Review

**Mistake:** Only working in "Show After" mode and submitting without reviewing changes.

**Result:** Miss unintended changes, surprise stakeholders with unexpected impact.

**Fix:** Always toggle to "Show Changes" before finalizing or submitting.

## Advanced Protips

### ✅ Use Scenarios for "What-If" Analysis

**Best practice:** Create multiple scenarios to compare different approaches.

**Example:**
- Scenario A: Aggressive hiring (50 new positions)
- Scenario B: Moderate hiring (25 new positions)
- Scenario C: Reorganize existing team (0 new positions)

Compare cost, timeline, and outcomes to choose the best approach.

### ✅ Create "Reference Scenarios" You Never Submit

**Best practice:** Create scenarios purely for analysis that you don't intend to implement.

**Use cases:**
- Test impact of different salary adjustments
- Model "what would happen if..." questions
- Create comparison baselines
- Explore organizational structure alternatives

Tag these as "Analysis Only" or "Reference" so people know they're not meant for approval.

### ✅ Leverage Scenario Comparison Features

**Best practice:** When deciding between approaches, use scenario comparison to see side-by-side impact.

**What to compare:**
- Headcount differences
- Cost impact differences
- Different effective date timelines
- Structural alternatives

## Quick Reference Checklist

**Starting a new scenario:**
- [ ] Use a descriptive name
- [ ] Add relevant tags and symbols
- [ ] Set scenario description with goals and owner
- [ ] Determine scope and timeline

- [ ] Set effective dates for time-based changes

- [ ] Review in "Show Changes" mode

- [ ] Export key views for documentation
- [ ] Write clear justification

**After approval:**
- [ ] Export final approved state
- [ ] Communicate to stakeholders
- [ ] Coordinate implementation with HRBP/Admin
- [ ] Archive or delete working drafts
