# Scenario Symbols

As you make changes in scenarios, Agentnoon adds **visual symbols** to position cards to indicate what changed. This guide explains each symbol and how to use them effectively.

---

## Why Symbols Matter

Symbols help you and collaborators quickly understand changes without reading detailed change logs.

**Benefits:**
- Scan org chart visually for changes
- Immediately identify what's different from baseline
- Communicate changes to stakeholders intuitively
- Review scenarios efficiently before approval
- Catch unintended changes at a glance

---

## Symbol Guide

### ➕ Newly Added Position (Green Icon)

**What it means:** This position was added in the scenario (didn't exist in Main Org).

**Visual:** Green icon in bottom-left corner of position card.

**Example:** New "Software Engineer" position created for Q2 hiring.

**When you'll see it:**
- Adding positions for growth
- Creating backfill positions
- New roles not in current org structure
- Headcount expansion scenarios

---

### ❌ RIF / Layoff (Red Icon)

**What it means:** Position marked for Reduction in Force (layoff/elimination).

**Visual:** Red icon or strikethrough on position card.

**Example:** "Account Manager" position closed due to budget cuts.

**When you'll see it:**
- Budget cut scenarios
- Restructuring with role elimination
- Cost reduction planning
- Downsizing exercises

**Important distinction:** RIF means involuntary termination, tracked separately from voluntary exits.

---

### 🚪 Exit (Orange Icon)

**What it means:** Position marked as voluntary departure (resignation, retirement).

**Visual:** Orange icon on position card.

**Example:** "VP Sales" retiring, position closed as exit.

**When you'll see it:**
- Retirement planning
- Anticipated resignations
- Natural attrition scenarios
- Succession planning with departures

**Important distinction:** Exit means voluntary departure, different from RIF.

---

### ✏️ Edit (Blue Icon)

**What it means:** Position attributes modified (title, salary, department, etc.) but position not added or closed.

**Visual:** Blue icon on position card.

**Example:** "Marketing Coordinator" title changed to "Marketing Manager" with salary increase.

**When you'll see it:**
- Promotions (title and salary changes)
- Compensation adjustments
- Department transfers (with same manager)
- Job title standardization
- Attribute corrections

---

### 🔀 Move (Purple Arrow Icon)

**What it means:** Position moved to different manager (reporting relationship changed).

**Visual:** Purple arrow icon on position card.

**Example:** "Product Manager" moved from VP Product to VP Engineering.

**When you'll see it:**
- Reorganizations
- Team restructuring
- Reporting line changes
- Matrixed to new manager
- Cross-functional moves

**Note:** Moves are organizationally significant but may not change cost.

---

### 🪑 Bench (Yellow Icon)

**What it means:** Employee moved to bench (removed from org chart but not closed/terminated).

**Visual:** Yellow icon on position card.

**Example:** Employee temporarily removed from structure during reorg planning.

**When you'll see it:**
- Restructuring in progress
- Temporary holding during reorganization
- Uncertain placement scenarios
- Planning before final decision

**Note:** Bench is temporary state, not final outcome.

---

### 📎 Detach (Gray Icon)

**What it means:** Employee detached from position, leaving position vacant.

**Visual:** Gray icon, position card shows no employee name.

**Example:** Current employee removed, position left open for backfill.

**When you'll see it:**
- Creating vacancy for new hire
- Preparing for backfill
- Succession planning
- Removing current employee but keeping role

**Important:** Position remains open, not closed.

---

### 🔒 Closed Position (Lock Icon)

**What it means:** Vacant position that has been filled and closed (no longer open requisition).

**Visual:** Lock icon on position card.

**Example:** Open "Software Engineer" req filled, position closed.

**When you'll see it:**
- Closing filled requisitions
- Removing open positions from plan
- Finalizing hiring scenarios
- Budget reallocation

---

## Symbol Combinations

Sometimes positions have **multiple symbols** indicating multiple changes.

**Example scenarios:**

**Move + Edit:**
- Position moved to new manager AND title/salary changed
- Shows: Purple arrow + Blue edit icon

**Detach + Edit:**
- Employee removed from position AND position details changed
- Shows: Gray detach icon + Blue edit icon

**Add + Edit:**
- New position added AND immediately edited before saving
- Shows: Green add icon + Blue edit icon

## Using Symbols Effectively

### Quick Visual Review

**Scan for changes quickly:**
1. Open scenario
2. Visually scan org chart for colored icons
3. Immediately see what changed without reading Change Tracker
4. Focus attention on areas with most symbols

**Speed up reviews:** Symbols let you review 100+ changes in seconds.

---

### Communicating with Stakeholders

**Share scenarios visually:**
1. Share scenario with stakeholders
2. Symbols provide intuitive understanding
3. No explanation needed for standard changes
4. Stakeholders see impact immediately

**Color coding helps:** Green (growth), Red (cuts), Blue (changes), Purple (restructure).

---

### Review Before Approval

**Final checks:**
1. Scan entire org chart for symbols
2. Ensure all symbols match intent
3. Check for unintended changes (accidental edits)
4. Verify no surprise symbols appear

**Common issues to catch:**
- Accidental moves (purple arrows where not intended)
- Unintended edits (blue icons on unchanged positions)
- Missing symbols (expected change not showing)

---

### Exporting with Symbols

**Include symbols in exports:**
1. Open scenario
2. Click **Export** → **Org Chart**
3. Select **Include Symbols** option
4. Export to PDF
5. Symbols visible in printed/shared charts

**When to use:**
- Presentations to leadership
- Board materials
- Stakeholder review documents
- Printed handouts for meetings

---

## Symbol Settings

### Toggling Symbol Visibility

**Hide/show symbols:**
1. Open scenario
2. Look for **View** or **Settings** menu
3. Toggle **Show Symbols** or **Show Change Indicators**
4. Symbols appear/disappear on position cards

**When to hide:**
- Focusing on org structure only
- Presenting final approved state
- Reducing visual clutter
- Comparing structures without highlighting changes

**When to show:**
- Reviewing changes
- Explaining what changed
- Approval workflows
- Collaborating on scenarios

---

### Symbol Legends

**Accessing symbol guide:**
- Many systems include **symbol legend** or **help icon**
- Hover over icons for tooltips
- Check documentation for full reference
- Share legend with stakeholders unfamiliar with system

## Common Patterns

### Reorganization Scenario

**Expected symbols:**
- 🔀 **Lots of purple arrows** (many positions moving to new managers)
- ✏️ **Some blue edits** (titles or responsibilities changing)
- ➕ **Few green adds** (maybe some new coordination roles)
- ❌ **Possibly some red** (if consolidating roles)

**What to check:** Ensure all moves are intentional.

---

### Growth/Hiring Scenario

**Expected symbols:**
- ➕ **Many green adds** (new positions for headcount expansion)
- 📎 **Some gray detaches** (if backfilling departures)
- ✏️ **Few blue edits** (maybe promotions)

**What to check:** Ensure all new positions have correct salary/details.

---

### Budget Cut Scenario

**Expected symbols:**
- ❌ **Many red icons** (positions being eliminated)
- 🔀 **Some purple arrows** (restructuring around cuts)
- ✏️ **Few blue edits** (role consolidation)

**What to check:** Ensure remaining org structure still functions.

---

### Succession Planning Scenario

**Expected symbols:**
- 🚪 **Orange exit** (departing leader)
- ➕ **Green add** (new successor position or backfill)
- 🔀 **Purple arrows** (reporting relationships shifting)
- ✏️ **Blue edits** (promotions or title changes)

**What to check:** Ensure smooth transition of responsibilities.

---

## Troubleshooting

**Problem:** Symbols not showing on position cards.
- **Solution:** Refresh page. Check if symbols are toggled off in view settings. Verify changes were saved.

**Problem:** Wrong symbol appearing.
- **Solution:** Review change details. May need to undo and redo action correctly. Check if multiple changes occurred.

**Problem:** Symbol appears but change wasn't intended.
- **Solution:** Undo the change. Review what action triggered it. Be more careful with drag-and-drop.

**Problem:** Expected symbol not showing.
- **Solution:** Verify change was saved. Check if change is relative to correct baseline. Refresh scenario.

**Problem:** Too many symbols, hard to see org structure.
- **Solution:** Toggle symbols off temporarily. Filter to specific department. Export without symbols for cleaner view.

---

## Best Practices

1. **Check symbols before sharing** - Ensure they accurately reflect intended changes
2. **Use symbol patterns to QA work** - Unexpected symbol patterns indicate mistakes
3. **Include symbol legend when presenting** - Not all stakeholders know what they mean
4. **Toggle symbols strategically** - Hide when focusing on structure, show when reviewing changes
5. **Export with symbols for reviews** - Help reviewers understand what changed
6. **Learn common patterns** - Recognize normal symbol patterns for each scenario type
