# Department Lead Checklist

Guide for managers planning department changes, team growth, and reorganizations.

---

## Quarterly Planning

**Estimated time: 3-5 hours per quarter**

Use this workflow for regular quarterly planning cycles.

### Preparation (30 minutes)

1. Review current team structure and headcount
2. Identify hiring needs for next quarter
3. Anticipate potential attrition
4. Gather budget information from Finance

### Create Scenario (15 minutes)

1. Click "Create Scenario"
2. Name it: "[Quarter] [Year] [Department] Plan" (e.g., "Q2 2026 Engineering Plan")
3. Choose Full Org or filter to your department
4. Add description explaining the planning scope
5. Click Create

### Model Hiring Needs (1-2 hours)

**Add new positions:**
1. Navigate to your team in the org chart
2. Click "+ Add Position" for each role
3. Set hire dates for phased hiring (spread across the quarter)
4. Assign salaries (use rate cards if available)
5. Set reporting relationships (manager assignments)

**Tips:**
- Stagger hire dates to reflect realistic recruiting timelines
- Consider ramp time for new hires
- Use consistent titles from your rate cards

### Model Attrition (30 minutes)

1. Close positions expected to turn over
2. Set termination dates if known
3. Add backfill positions with hire dates after departures

### Analyze Impact (30 minutes)

1. Open OpEx Panel to view:
   - Net headcount change (+/- positions)
   - Net cost change (+/- workforce cost)
   - List of all additions and closures
2. Switch to Forecast view to see monthly/quarterly ramp
3. Check that budget aligns with department targets

### Export and Submit (30 minutes)

1. Export forecast data for budget meetings
2. Share scenario link with stakeholders for feedback
3. Make any adjustments based on feedback
4. Submit for approval via OpEx Panel
5. Track approval status

**Learn more:** [Building Headcount Forecasts](../../forecast/building-headcount-forecasts.md)

## Organizational Changes

**Estimated time: 2-4 hours per reorg**

Use this workflow for reorganizations, restructures, and reporting changes.

### Preparation (30 minutes)

1. Document the goals of the reorganization
2. Sketch out the new team structure
3. Identify positions that will move
4. Identify new positions needed (e.g., new managers)

### Create Scenario (15 minutes)

1. Click "Create Scenario"
2. Name it describing the change (e.g., "Q2 Engineering Reorg" or "Support Team Restructure")
3. Choose Full Org
4. Add detailed description of changes
5. Click Create

### Model New Structure (1-2 hours)

**Add new positions:**
1. Create new management or lead positions first
2. Set hire dates or effective dates for transitions
3. Assign salaries based on level and scope

**Move existing positions:**
1. Drag position cards to new reporting relationships
2. Or edit "Manager" field in position details
3. Update effective dates if changes are phased

**Close redundant positions:**
1. Right-click positions being eliminated
2. Select "Close Position"
3. Set termination dates

### Validate Structure (30 minutes)

1. Check Span of Control for all managers
   - Typical range: 4-10 direct reports
   - Flag managers with too few (<3) or too many (>12) reports
2. Verify all positions have correct managers
3. Check for any broken reporting relationships

### Phase Changes Over Time (30 minutes)

If the reorg happens in stages:
1. Use effective dates to phase changes
2. Model interim states before final structure
3. View timeline in Forecast to see transitions

### Get Feedback and Submit (30-60 minutes)

1. Share scenario with stakeholders (HR, peer managers, leadership)
2. Walk through the changes in a meeting if complex
3. Make adjustments based on feedback
4. Document rationale in scenario description
5. Submit for approval via OpEx Panel

**Learn more:** [Planning a Reorganization](../../use-case-tutorials/planning-reorganization.md)

## Common Department Planning Tasks

### Backfill Planning (30 minutes)

When someone leaves:
1. Create a scenario for the backfill
2. Close the departing person's position (set termination date)
3. Add a new position with hire date (allow for recruiting time)
4. Analyze cost impact if salary changes
5. Submit for approval

### Promotion Planning (15-30 minutes)

When promoting someone:
1. Create a scenario for the promotion
2. Edit the position to update:
   - Title
   - Salary (new compensation)
   - Effective date of promotion
   - Manager (if role changes, e.g., IC to manager)
3. Submit for approval

### Team Expansion (1-2 hours)

When growing your team:
1. Create a scenario for team growth
2. Add all new positions with:
   - Staggered hire dates (realistic timeline)
   - Appropriate levels (junior, mid, senior)
   - Manager assignments
3. Check if you need to add a manager for span of control
4. Analyze budget impact
5. Submit for approval

## Tips for Department Leaders

### Before You Start

- Complete the [Quick Start Checklist](../quick-start-checklist.md) to understand the platform
- Review [Scenarios Overview](../../scenarios/overview.md)
- Watch relevant [Video Tutorials](../../start-here/video-tutorials.md)

### Best Practices

- **Name scenarios clearly:** Use consistent naming like "[Quarter] [Year] [Department] [Type]"
- **Use descriptions:** Explain the "why" behind your changes
- **Stagger hire dates:** Reflect realistic recruiting and onboarding timelines
- **Check Span of Control:** Keep managers within healthy ranges (4-10 reports)
- **Export regularly:** Save forecast data for your records
- **Collaborate early:** Share scenarios with stakeholders before submitting

### Common Mistakes to Avoid

- Don't add all hires on the same date (unrealistic)
- Don't forget to model attrition
- Don't skip approval submission (scenarios aren't official until approved)
- Don't make changes directly in Main Org (always use scenarios)
